## 2. Базовая версия (программный CRC32)

Исходная реализация – побайтовый расчёт через битовый цикл.

```c
uint64_t HashCrc32(const char* key) 
{
    uint32_t crc = 0xFFFFFFFF;
    while (*key) 
    {
        crc ^= (uint8_t)(*key);
        for (int i = 0; i < 8; i++)
            crc = (crc & 1) ? (crc >> 1) ^ 0xEDB88320 : (crc >> 1);
        key++;
    }
    return ~crc;
}
```

Время выполнения: 35.767 с (точка отсчёта).

## 3. Оптимизация №1: аппаратный CRC32 (intrinsics)

Одна инструкция crc32 заменяет внутренний битовый цикл из 8 операций.

Реализация:

```c
uint64_t HashCrc32 (const char* key) 
{
    uint32_t crc = 0xFFFFFFFF;
    while (*key) crc = _mm_crc32_u8 (crc, *key++);
    return ~crc;
}
```

Результат:
Время → 20.303 с (ускорение 1.76×, +43.6% относительно базовой версии).

![Профиль после ускорения хешфункции](Снимок экрана от 2026-05-11 11-38-29.png)

Вывод: замена программного CRC32 на аппаратный – самая эффективная оптимизация (основной прирост).

## 4. Оптимизация №2: собственная AVX2‑функция сравнения строк

Я заменяю универсальный `strcmp`на свой в котором выравниваю строки по 32 байта, и дополняю их нулями. Это позволяет использовать `vmovdqa` и сравнивать 32 байта за одну операцию.

```asm
section .text
global MyAvxStrcmp

MyAvxStrcmp:
            ; ymm0 - a, ymm1 - b
            mov rsi, rcx           ; rsi = a
            mov rdi, rdx           ; rdi = b
            vmovdqa ymm0, [rsi]
            vmovdqa ymm1, [rdi]
            ; Сравнивание побайтово (байты равны -> получается 0xFF в ymm2)
            vpcmpeqb ymm2, ymm0, ymm1
            vpmovmskb eax, ymm2
            ; Если все 32 бита установлены (0xFFFFFFFF) -> строки равны
            cmp eax, 0xFFFFFFFF
            je .equal

            not eax
            tzcnt ecx, eax
            movzx edx, byte [rsi + rcx]
            movzx eax, byte [rdi + rcx]
            sub  edx, eax                 
            mov  eax, edx
            ret

.equal:
            xor eax, eax
            ret
```

время → 20.056 с (ускорение 1.78×, +1.2% относительно предыдущей версии)

![Профиль после замены стркмп](Снимок экрана от 2026-05-12 12-42-52.png)

Теперь `MyAvxStrcmp` – самая горячая точка. Ускорение небольшое, стандартный `strcmp` итак использует AVX2 и хорошо оптимизирован. Моя функция чуть быстрее за счёт отсутствия проверок длины и работы с выровненными данными.

## 5. Оптимизация №3: линеаризация списков

Узлы списка выделялись через `calloc` независимо → разбросаны по памяти. При обходе префетчер не может предугадать следующий адрес → кэш-промахи.

После заполнения таблицы все узлы каждого списка перестраиваются в непрерывный массив (последовательное расположение в памяти).

| Показатель | Без линеаризации | С линеаризацией | Изменение |
|------------|------------------|----------------|------------|
| L1-dcache-load-misses | 872,8 млн | 343,8 млн | -60,6% |
| LLC-load-misses | 520,8 тыс | 414,1 тыс | -20,5% |

**Результат:** время → 18.908 с (ускорение +6% относительно версии 4, общее ускорение 1.89×)

Время в `ListFindNode` остаётся высоким, но общее время снизилось за счёт уменьшения задержек при доступе к памяти.

## 6. Неудачная оптимизация: фильтр первых 8 байт

Перед вызовом `MyAvxStrcmp` решил попробовать быстро сравнивать первые 8 байт ключа (ассемблерная вставка `movq` + `cmp` + `sete`). Если префиксы не совпадают – строки точно разные, и дорогой вызов не нужен.

```c
  while (current != dummy) 
    {
        uint64_t node_prefix = 0;
        __asm__ ("movq (%1), %0" : "=r" (node_prefix) : "r" (current->key) : "memory");
        int equal = 0;
        __asm__ ("cmp %2, %1; sete %0" : "=r" (equal) : "r" (node_prefix), "r" (key_prefix) : "cc");

        if (equal && MyAvxStrcmp (current->key, key) == 0)  return current;
        current = current->next;
    }
```

Время → 22.4 с (на **10% хуже** версии без фильтра)

![Профиль после замены стркмп](Снимок экрана от 2026-05-12 12-40-37.png)

| Параметр | Без фильтра (20.156 с) | С фильтром (22.4 с) | Изменение |
|----------|------------------------|---------------------|------------|
| cycles (млрд) | 100,7 | 112,0 | +11% |
| instructions (млрд) | 180,0 | 167,9 | -7% |
| IPC | 1,79 | 1,50 | -16% |
| branch-misses (млн) | 13,8 | 14,7 | +6,5% |

**Почему не сработало:**
1. **Накладные расходы:** на каждом узле добавились 3 инструкции.
2. **Ухудшение предсказания ветвлений:** новая условная ветвь сбивает предсказатель.
3. **`MyAvxStrcmp` быстра:** сравнение 32 байт через AVX2 занимает всего несколько тактов. Экономия от её редких вызовов не перекрывает затраты на фильтр.
4. **Двойная загрузка:** первые 8 байт загружаются дважды (фильтром и внутри `MyAvxStrcmp`).
